# Decisions

One entry per block. What was chosen, what was rejected, what was deferred.

## Block 1 — scaffold

Decided: pnpm monorepo on Next 16 and Nest 11; Prisma 7 with the `pg` driver adapter, since v7 has no query engine and pool settings moved off the connection string; a `sort_rank` generated column so folders sort before files under an all-ascending index; `nodes_name_uniq` covering `uploading` rows so a name conflict fires at `/files/init` rather than after the bytes move; JWT verified locally via JWKS (the project uses ES256) with the HS256 path kept as a fallback; liveness `/health` split from readiness `/health/ready`, which gates the deploy.

Alternatives considered: `ORDER BY type DESC` instead of `sort_rank` — rejected because a mixed-direction sort cannot be served by an all-ascending btree and breaks tuple-comparison keyset; excluding `uploading` rows from the unique index — rejected because it moves the conflict to after the upload and lets two concurrent uploads of the same name both pass init; RLS as the access mechanism — rejected per `docs/architecture.md`, it stays a deny-all backstop; a single `/health` serving both liveness and the deploy gate — rejected because tolerating database blips and refusing traffic on a broken database cannot both live in one status code.

Deferred: P2002 handling when a Supabase email already belongs to another local `users` row, and eviction for the guard's `synced` map — both wait for Block 5, where pending shares resolve by email and the semantics of a changed address get settled; a closure table, which stays unnecessary until ancestor-direction queries appear.

## Block 2 — rooms, folders, navigation

Decided: TanStack Query for all data, because `react-hooks/set-state-in-effect` makes a fetching effect an error rather than a warning, and `useMutation`/`useInfiniteQuery` are what the optimistic rename and keyset paging in `docs/ui.md` need; folders and root nodes are written with `status='ready'` explicitly, since the column default is `uploading` and listings filter it out; the keyset cursor carries Postgres' own `lower(name)` rather than recomputing it in JS, where the collation would drift from the index; a mutation refused for a requester who *can* read returns `403`, not `404`, because existence is already known to them; design tokens were pulled forward from Block 6 so the two screens were not built twice.

Alternatives considered: server components with `@supabase/ssr` cookie sessions — rejected because `docs/architecture.md` has the browser hold the anon key and send a JWT, and cookie sessions would be a second auth mechanism; splicing a created folder into the cached page instead of invalidating — rejected because the list is keyset-ordered and a guessed insertion point shows the row twice or in the wrong place; hand-rolled dialogs instead of shadcn — rejected because `docs/ui.md` requires a focus trap and focus restoration in every modal, which Base UI already gets right; naming the next/font variable `--font-sans` — rejected after it shipped, because Tailwind emits `:root { --font-sans: … }` at the same specificity and the variable referenced itself, dropping the whole app to the browser's default serif.

Deferred: table virtualisation, which `docs/ui.md` requires but which only bites once files exist — Block 6; a decision on dark mode, since shadcn generated a full `.dark` token block that nothing activates — Block 6; unique room names and `PATCH`/`DELETE /rooms/:id`, because a root node has `parent_id IS NULL` and escapes `nodes_name_uniq`, and the real problem is that a mistyped room name cannot be corrected at all — Block 4.

## Block 3 — upload

Decided: the `file_versions` row is written at `init` alongside the node, with `size_bytes = 0` as the in-flight marker — a reading that is only sound because zero-byte files are rejected, so the sweeper and `/complete` share one invariant; the storage key is `{roomId}/{nodeId}/{versionId}.pdf`, which makes "Replace never overwrites bytes" structural rather than a convention; the conflict answer travels as `onConflict: error | keepBoth | replace` and is applied server-side by retrying the insert; `init` returns the `versionId`, and `complete` and `cancel` name it, so two overlapping replacements verify their own bytes instead of each other's; 50 MB, enforced in the browser, in the API at both ends, and by the bucket itself; the sweeper is a plain `setInterval`. Two additions to the frozen contract, both raised first: `DELETE /files/:id` to release a cancelled name immediately, and `name` in the `init` response so the queue shows what the file was actually stored as.

Alternatives considered: letting the browser pick the "(2)" suffix and retry — rejected because two uploads of one name compute the same suffix and the loser is refused a name nobody typed; a partial unique index allowing one in-flight version per node instead of passing `versionId` — rejected because it reinstates exactly the abandoned-upload block that the fifteen-minute retry exists to dissolve; `@nestjs/schedule` — rejected because one fixed interval needs neither a cron parser nor a dependency; the `/object/info` endpoint — unnecessary, since the `Range: bytes=0-7` read already carries the total size, the stored content type and the ETag in one call; treating any non-206 probe response as a missing object — rejected after review, because a transient Storage fault would then delete a file that had arrived intact and tell the user it never finished.

Deferred: objects orphaned by a hard delete of a room, which no sweep can find once the `file_versions` rows are gone — this only becomes reachable when `DELETE /rooms/:id` lands in Block 4, and the answer there is a prefix delete before the rows go; resuming an interrupted upload rather than restarting it, worth doing only if files large enough to notice become common.

## Block 4 — viewing and operations

Decided: `react-pdf` over an `<iframe>`, because an iframe cannot report whether it rendered anything and the "Preview unavailable" cell of the state matrix would be unreachable — its worker, CMaps, fonts and WASM decoders are copied out of the pinned `pdfjs-dist` at build time and served from `/pdf`, so a document that renders does not depend on a CDN; the preview is a `?file=` param pushed with `history.pushState` rather than a sixth route, so the folder underneath is neither unmounted nor refetched; `PATCH /nodes/:id` carries rename and move together, since a move is that same single-row UPDATE plus a prefix rewrite sharing its transaction, and the subtree's maximum depth is measured before the transaction opens because `nodes_depth_max` is a CHECK constraint and finding out halfway through means rolling back real work; the destination picker walks down one level at a time, reusing the listing endpoint and its keyset paging, on the reasoning `docs/ui.md` used to reject a sidebar tree; rooms gain `deleted_at` and a partial `(owner_id, lower(name))` unique index, with the migration renaming pre-existing duplicates rather than failing on data that predates the constraint. Two contract additions, both raised first: `onConflict` on `PATCH /nodes/:id`, and `PATCH`/`DELETE /rooms/:id`.

Alternatives considered: refetching the signed URL on a timer while the document is open — unnecessary, because Supabase sends no `Access-Control-Expose-Headers`, so pdf.js never sees `Accept-Ranges`, never enables range mode, and reads the whole document in one request; the refetch that matters is on reopening, which `gcTime: 0` gets for free. A right-click menu alone — rejected as invisible, absent on touch and unreachable from the keyboard, so `⋯` is the control and right-click the accelerator. Splicing the renamed row into the cached listing — rejected because the list is keyset-ordered and the new position is not derivable on the client. A hard `DELETE /rooms/:id` — rejected because it destroys the `shares` rows Block 5 needs to answer `410` rather than `404`. "Replace" on a move is not "Replace" on an upload and is built differently: an upload versions the file already there, while a move brings a node with its own history and there is no honest way to merge two, so the blocker is tombstoned — offered only file-over-file, since replacing a folder would delete a subtree behind a button labelled "Replace".

Four things were wrong until clicking found them, and each had a wrong reason behind it. `isUniqueViolation` read only `P2002` and a bare `23505`, but Prisma's driver adapter reports a `$executeRaw` failure as `P2010` with the Postgres code nested underneath — so every rename and move conflict escaped as an unexplained `500`, and Block 3's version-number retry had been silently dead too. The suggested name was the next number up rather than the first free one, justified by a TOCTOU argument that does not apply: the suggestion is computed after `23505` has already fired and decides nothing, so it now asks in one indexed `= ANY` which candidates are taken. The magic-byte check demanded `%PDF-` at offset zero, which rejected a real document — a PDF inside a PKCS#7 signature container, header at offset 70, that pdf.js reads without complaint — so both checks now scan the first kilobyte, as every reader does. And the three row dialogs lived inside the row their own optimistic edit removes, so the conflict question unmounted before the server answered; they now live above the listing and act on a snapshot.

Deferred: reclaiming storage objects when a node or room is deleted. The sweeper only recognises an abandoned upload — a version with `size_bytes = 0` — and a deleted file's version is complete, so its object outlives the tombstone. Doing it properly means a second sweep that nulls `current_version_id`, deletes the `file_versions` rows and only then removes the objects, behind a grace period long enough to keep the delete recoverable; it is invisible in the product and the one place a bug destroys data, so it is written down in `README.md` rather than rushed. Also deferred: cross-room moves, which would mean rewriting `data_room_id` across a subtree and re-deriving permission against a different owner.

## Block 5 — sharing

Decided: every share carries its own token, named ones included — `WRONG_ACCOUNT` can only be told to someone who presents a capability, because a stranger on a plain node URL must get `404`, so a named share with no URL of its own makes the three-way answer unreachable; `/s/:token` is a four-route public mirror that resolves the token and hands the share to the same services the private routes use, leaving the permission rule, the tombstone order and the 404/410 answers in one place; the breadcrumb trail is cut to the highest ancestor the requester may actually read, which closed a leak on the private route that the share routes had already avoided by accident; the two overview lists are tabs on `/` rather than a sixth screen, because a share panel bound to an item cannot answer "where did I share things" and is no use at all to a recipient.

Alternatives considered: named shares without a token — rejected, it either hides the wrong-account case behind `404` or turns `403` into an oracle for which node ids exist; `@nestjs/throttler` — rejected for the reason Block 3 rejected `@nestjs/schedule`, one fixed window needs neither a cron parser nor a dependency; a separate read-only viewer for recipients — rejected as a second implementation of the listing, the preview and the states, and so a second place for a permission check to go missing; showing the percentage inside a growing pill — rejected after it shipped, a centred label that gains a digit twitches the whole way down, so the geometry is fixed and the one moving thing is a line along the top edge.

Two were wrong until a real document was opened. `<Page>` drops its own `loading` element when pdf.js hands over the page *object*, seconds before `render()` has drawn anything, so the placeholder left while the canvas was still blank — it now stays until `onRenderSuccess`, with the page hidden underneath it by `visibility`, never `display`, because the width the pages render at is measured from that element. And mounting every page at once put the only page anyone was waiting for at the back of the rasterising queue, so pages now render a screen ahead of the scroll, against the panel that scrolls rather than the window.

Deferred: an owner opening their own named link is told it is for a different account — truthful, and skipping the check for them costs a lookup per request, so it waits until that is worth paying; expired shares are hidden rather than listed as history, which is why an expired invitation had to be retired on collision rather than shown with a Revoke button; `docs/ui.md` still describes `/` as the owner's data rooms, which is now narrower than the screen — the route count it actually governs is unchanged at five.
